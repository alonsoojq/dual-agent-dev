# Repository context example

Inactive example. Copy/adapt as a root `.dual-agent-context.md` for shareable
facts, or use private configuration as described in
[Configuration](../references/configuration.md).

- Repository identity: derive from the actual root and project documentation.
- Current contracts: link the project's authoritative specifications.
- Components and boundaries: list only observed areas.
- Verification: point to existing build/test definitions; inspect effects before running.
- External facts: list what repository inspection cannot establish.
- Reports: use the team's existing documentation location.
- Private context: reference only an approved private location, without secret values.

A CLI without persistent storage needs no database audit unit. A workspace with
binary assets needs suitable metadata/format inspection and explicit coverage
limits. These examples describe method, not facts about the target repository.
